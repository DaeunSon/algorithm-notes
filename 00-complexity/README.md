# 시간복잡도

## 정의 : Big-O가 무엇인가

- 입력 n을 기준으로 실행되는 연산 횟수의 상한
- 상수와 낮은 차수는 버린다
- 최악의 경우가 기준

```
3n² + 5n + 2   →  O(n²)
 └ 가장 빨리 커지는 항만 남기고, 앞의 상수(3)도 버린다
```

입력이 커질 때 **얼마나 빨리 느려지는가**를 보려는 것이라서, 작은 항과 상수는 무시한다.

## 입력 크기별 허용 복잡도

기준: **자바는 1초에 대략 1억 번 안팎의 단순 연산**을 한다. (정확한 값이 아니라 판단용 감각이다.)

| n의 크기 | 쓸 수 있는 복잡도 | 예 |
|---|---|---|
| ~20 | O(2ⁿ) | 완전탐색, 백트래킹 |
| ~1,000 | O(n²) | 이중 반복 |
| ~10⁵ ~ 10⁶ | O(n log n), O(n) | 정렬, 해시, 슬라이딩 윈도우 |

n이 10⁵일 때 실제 연산 횟수:

| 복잡도 | 연산 횟수 | 판단 |
|---|---|---|
| O(n) | 10⁵ | 순식간 |
| O(n log n) | 약 1.7 × 10⁶ | 순식간 |
| O(n²) | 10¹⁰ | 약 100초 → **시간 초과** |

**문제를 읽으면 제일 먼저 n의 최댓값을 본다.** 이 값으로 쓸 수 없는 방법을 걸러낸다.

## 복잡도 종류와 대표 예

| 복잡도 | 예 |
|---|---|
| O(1) | 해시 조회 (`map.get`), 배열 인덱스 접근 |
| O(log n) | 이진 탐색 |
| O(n) | 한 번 순회 |
| O(n log n) | 정렬 |
| O(n²) | 이중 for문 |
| O(2ⁿ) | 모든 부분집합 탐색 |

**O(log n)의 감각**: 매번 절반씩 줄이면 끝나기까지 log₂ n 번이다. n = 1,000,000이어도 약 20번이다.

```java
for (int i = 1; i <= n; i *= 2) { ... }   // i가 1, 2, 4, 8, ... → 약 log n 번
```

## 코드에서 복잡도 세는 법

반복문마다 "한 바퀴가 몇 번 도는가"를 적고 곱한다.
중요한 건 안쪽 반복이 "무엇에 비례하는가".

```java
for (int i = 0; i < n; i++)          // n번
    for (int j = i + 1; j < n; j++)  // 평균 n/2번 → 합쳐서 n(n-1)/2 → O(n²)
        ...
```

**중첩 반복이라고 항상 O(n²)이 아니다.** 안쪽이 n에 비례하지 않고 작은 상수에 묶여 있으면 곱해도 O(n)이다.

```java
for (String s : phone_book)              // n개 (최대 100만)
    for (int i = 1; i < s.length(); i++) // 번호 길이: 최대 20 (상수)
        set.contains(s.substring(0, i));
// 100만 × 20 → O(n)
```

순서대로 이어진 반복은 **더한다**, 중첩된 반복은 **곱한다**.

```java
for (...) {...}   // O(n)
for (...) {...}   // O(n)   → 합: O(n) + O(n) = O(n)
```

## 자바 자료구조, 메서드별 비용

시험에서 시간 초과가 나는 숨은 원인은 대부분 **반복문 안에서 호출한 메서드가 O(n)**인 경우다.

| 자료구조 | 연산 | 복잡도 |
|---|---|---|
| 배열 | 인덱스 접근 `arr[i]` | O(1) |
| `ArrayList` | `get(i)`, `set(i, x)` | O(1) |
| | 끝에 `add(x)` | O(1) (평균) |
| | `contains(x)`, `indexOf(x)` | **O(n)** |
| | 중간에 `add(i, x)`, `remove(i)` | **O(n)** (뒤를 밀거나 당김) |
| `HashMap`, `HashSet` | `put`, `get`, `containsKey`, `contains`, `remove` | O(1) (평균) |
| `TreeMap`, `TreeSet` | 삽입, 조회, 삭제 (키가 정렬된 상태 유지) | O(log n) |
| `ArrayDeque` | 양쪽 끝 `push/pop/add/poll` | O(1) |
| `LinkedList` | 양쪽 끝 삽입, 삭제 | O(1) |
| | `get(i)` | **O(n)** |
| `PriorityQueue` | `add`, `poll` | O(log n) |
| | `peek` | O(1) |
| | `contains`, `remove(x)` | **O(n)** |
| 정렬 | `Arrays.sort(arr)`, `Collections.sort(list)` | O(n log n) |
| `String` | `charAt(i)`, `length()` | O(1) |
| | `substring`, `equals`, `toCharArray` | O(길이) |
| | `s + t` (새 문자열 생성) | O(길이) |
| `StringBuilder` | `append` | O(1) (평균) |
| | `reverse`, `toString` | O(길이) |

참고

- 해시의 O(1)은 평균이다. 이론적으로 최악은 더 느릴 수 있지만 시험에서는 O(1)로 본다.
- `Arrays.sort`는 기본 타입 배열과 객체 배열의 내부 알고리즘이 다르다. 둘 다 O(n log n)으로 보면 충분하다. 정확한 내용은 자바 문서에서 확인한다.
- 표는 [Big-O Cheat Sheet](https://www.bigocheatsheet.com/)와 비교하며 공부한다. 자바 구현은 약간 다를 수 있으니 의심되면 공식 문서를 본다.

**표에서 굵게 표시한 O(n) 연산을 반복문 안에서 부르면 전체가 O(n²)이 된다.** (아래 "자주 하는 실수" 참고)

## 공간복잡도

실행하는 동안 **추가로 쓰는 메모리**의 크기다. 입력 자체는 보통 세지 않는다.

| 상황 | 공간복잡도 |
|---|---|
| 변수 몇 개만 사용 | O(1) |
| 크기 n인 배열, 리스트, 맵을 만듦 | O(n) |
| 재귀 호출 깊이 d | O(d) (호출 스택) |

**시간을 줄이려고 메모리를 쓰는 거래**가 흔하다.

| 방법 | 시간 | 공간 |
|---|---|---|
| Two Sum 이중 for문 | O(n²) | O(1) |
| Two Sum 해시맵 | **O(n)** | O(n) |

코딩 테스트에서는 보통 **시간이 더 중요**하다. 메모리 제한이 있는 문제만 공간을 따진다.

## 내가 겪은 사례

| 문제 | 느린 방식 | 빠른 방식 |
|---|---|---|
| 순서쌍의 개수 (n ≤ 10⁶) | `i`, `j` 이중 for → 약 1조 번 | `i`를 정하면 `j = n / i`로 정해지므로 한 반복 → O(n) |
| 전화번호 목록 (번호 ≤ 100만 개) | 모든 쌍 비교 → O(n²) | 각 번호의 접두어(최대 19개)를 해시에서 확인 → O(n) |
| 기사단원의 무기 (n ≤ 10⁵) | 번호마다 1부터 자기까지 나눠보기 → 약 50억 번 | 제곱근까지만 → 약 3천만 번, 배수 체 방식 → 약 120만 번 |
| 달리기 경주 (호출 ≤ 100만, 선수 ≤ 5만) | 호출마다 배열에서 탐색 → 약 500억 번 | `HashMap`으로 위치 조회 → 호출당 O(1) |
| 햄버거 만들기 (재료 ≤ 100만) | 완성할 때마다 배열을 당겨서 제거 → O(n²) | 스택(배열 + `top`) → O(n) |
| Two Sum | 이중 for문 O(n²) | 해시맵 O(n) |
| 중복 없는 가장 긴 부분 문자열 | 시작점마다 처음부터 다시 | 슬라이딩 윈도우: `left`, `right`가 각각 n번만 이동 → O(n) |
| 가장 긴 팰린드롬 | 모든 구간 검사 → O(n³) | 가운데에서 확장 → O(n²) |
| 문자열을 반복해서 이어붙이기 | `s = s + c` 반복 → O(n²) | `StringBuilder.append` → O(n) |

공통 패턴: **"같은 걸 다시 계산하거나 다시 찾는" 부분을 없애는 것**이 속도를 올리는 핵심이었다. (해시로 바로 찾기, 포인터를 한 방향으로만 움직이기, 한 번 계산한 걸 저장하기)

## 자주 하는 실수

- **반복문 안에서 `list.contains()`를 부른다.** 한 번 부르는 게 O(n)이라 전체가 O(n²)이 된다. → `HashSet`으로 바꾼다.
- **`String + String`을 반복문에서 계속 쓴다.** 매번 새 문자열을 만들어서 O(n²)이 된다. → `StringBuilder`
- **반복문 안에서 `remove(0)`처럼 앞쪽 원소를 지운다.** `ArrayList`는 뒤를 전부 당기는 O(n)이다. → 큐(`ArrayDeque`)나 인덱스 포인터를 쓴다.
- **n의 최댓값을 확인하지 않고 풀이를 정한다.** 이중 for문이 O(n²)이어도 n ≤ 1,000이면 통과한다. 반대로 n ≤ 10⁶인데 쓰면 시간 초과다.
- **중첩 반복은 무조건 느리다고 생각한다.** 안쪽이 상수(번호 길이 20 등)에 묶여 있으면 O(n)이다.
- **`int` 오버플로.** 복잡도 문제는 아니지만 큰 입력에서 같이 터진다. 곱셈이 있고 값이 크면 `long`을 쓴다.

## 연습

코드를 보고 복잡도를 먼저 맞혀본 뒤 답을 펼쳐서 확인한다.

**1.**
```java
for (int i = 0; i < n; i++) sum += arr[i];
```
<details><summary>답</summary>O(n)</details>

**2.**
```java
for (int i = 1; i <= n; i *= 2) count++;
```
<details><summary>답</summary>O(log n). i가 두 배씩 커져서 약 log₂ n 번만 돈다.</details>

**3.**
```java
for (int i = 0; i < n; i++) {
    if (list.contains(arr[i])) count++;    // list는 ArrayList
}
```
<details><summary>답</summary>O(n²). `contains` 한 번이 O(n)이고 그걸 n번 부른다. `HashSet`이면 O(n).</details>

**4.**
```java
String s = "";
for (int i = 0; i < n; i++) s += "a";
```
<details><summary>답</summary>O(n²). 매번 새 문자열을 만들어 길이만큼 복사한다. `StringBuilder`면 O(n).</details>

**5.**
```java
for (int i = 0; i < n; i++) {
    for (int j = 0; j < 20; j++) {
        // 상수 시간 작업
    }
}
```
<details><summary>답</summary>O(n). 안쪽이 20번으로 고정이라 20n이고, 상수를 버리면 O(n)이다.</details>

**6.**
```java
for (int i = 0; i < n; i++) {
    int[] small = Arrays.copyOf(arr, k);
    Arrays.sort(small);
}
```
<details><summary>답</summary>O(n · k log k). 반복 안에서 정렬하면 정렬 비용이 n번 곱해진다. k가 작으면 괜찮다.</details>

**7. 판단 연습**

n = 10⁵인 문제를 이중 for문으로 풀면 통과할까?
<details><summary>답</summary>통과하지 못한다. 10¹⁰번이라 약 100초가 걸린다. O(n log n)이나 O(n) 방법을 찾아야 한다.</details>
